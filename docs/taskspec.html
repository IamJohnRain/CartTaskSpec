TaskSpec Protocol · DataModel-first

TaskSpec 只描述 DSL 生成任务，不再承载 CardSpec

当前协议以 `harmony-card-generation-datamodel-first` 为依据。TaskSpec 保留用户需求中小模型生成 DSL 真正需要的内容项、DataModel、动作和素材；所有 DSL 硬规则统一放入 system prompt。

DSL-only最终只输出 genui，不输出 cardspec。
DataModel-first展示值优先使用完整表达式读取 DataModel。
规则进 promptTaskSpec 删除 rules.dsl，系统提示承载 DSL 硬规则。
动作内联action requirement 直接携带 onClick。
Top Level

顶层字段与是否必填

当前 schema 顶层只允许 7 个字段，全部必填。旧的 CardSpec、data capability、eventBindings 和 rules 模块已经移除。

字段是否必须说明示例
schema必须协议版本，固定为 `taskspec/v1`。"taskspec/v1"
rulesVersion必须规则集版本，固定为 `harmony-form-datamodel-first-rules/v1`。"harmony-form-datamodel-first-rules/v1"
userQuery必须原始用户需求，保留语义来源。"显示深圳温度并给我爸打电话"
task必须给小模型的任务说明，必须约束只输出 genui。"直接输出 genui..."
card必须卡片场景、尺寸、内容需求和约束。{"scenario":"device","size":"2x4"}
dataModel必须小模型第 3 行 updateDataModel.value 必须原样使用的数据。{"value":{"device":{...}}}
assets必须素材白名单；没有素材时为空数组。[]
Modules

具体模块说明

MODULE 01

版本与任务

schema / rulesVersion / userQuery / task

必须 `rulesVersion` 选择 DataModel-first 规则。`task` 只表达生成目标，不携带 DSL 规则细节。

示例
{
  "schema": "taskspec/v1",
  "rulesVersion": "harmony-form-datamodel-first-rules/v1",
  "userQuery": "给我做个好看的耳机桌面卡片...",
  "task": "根据本 TaskSpec 生成一个 genui 代码块。直接输出 genui，不输出解释或 cardspec。"
}
MODULE 02

card

卡片意图，不是布局方案

必须 `scenario` 表达卡片主要意图，`size` 只表达 2x2/2x4 目标，`requirements` 表达必须显示或可点击的内容项。

size新 skill 的 DSL 尺寸为 `2x2 = 140x140`、`2x4 = 300x140`。
action点击动作直接写在 requirement 的 `onClick` 中，不再使用 eventRef。
示例
{
  "scenario": "device",
  "size": "2x4",
  "requirements": [
    { "id": "device_name", "type": "identity", "label": "Free Clip 2", "dataPath": "/device/name", "required": true },
    { "id": "left_battery", "type": "metric", "label": "左耳电量", "dataPath": "/device/leftBatteryText", "required": true },
    {
      "id": "daily_30",
      "type": "action",
      "label": "每日30首",
      "onClick": [
        { "call": "clickToDeeplink", "args": { "bundleName": "", "abilityName": "", "uri": "..." } }
      ]
    }
  ],
  "constraints": ["整体简洁高级，有磨砂玻璃质感。"]
}
MODULE 03

dataModel

表达式和绑定的唯一数据源

必须 `dataModel.value` 必须被小模型原样写入 `updateDataModel.value`。所有 `dataPath`、表达式和原生绑定路径都应能从这里解析。

示例
{
  "value": {
    "device": {
      "name": "Free Clip 2",
      "leftBatteryText": "左耳 47%",
      "rightBatteryText": "右耳 95%"
    }
  }
}
MODULE 04

assets

素材白名单

必须 没有素材时写 `[]`。小模型只能使用这里声明的本地/资源路径，不得使用网络图、SVG 或未声明资源。

示例
[]
Removed

已移除模块

这些模块不再进入 TaskSpec。它们要么属于 system prompt，要么属于端侧 CardSpec 生成链路，要么已被内联到 requirements。

模块状态原因替代方式
rules.dsl移除DSL 硬规则是通用生成规则，不应每个 TaskSpec 重复。写入 system prompt。
cardSpec移除当前任务只让小模型生成 DSL，不生成 CardSpec。如端侧需要，另走 CardSpec 生成链路。
dataCapabilities移除小模型不负责选择端侧 data capability 或生成 dataBindings。用 dataModel 结构和 dataPath 表达 DSL 可绑定数据。
eventBindings移除顶层 eventRef 跳转增加冗余。action requirement 直接内联 onClick。
validation移除校验记录不是生成 DSL 的输入。由校验脚本输出报告。
capabilityGap移除能力缺口说明属于 Agent 决策过程，不进入小模型 DSL 输入。由上游流程处理。
Validation

校验要点

发送给小模型前

  • JSON 结构符合 `taskspec.schema.json`。
  • 不得包含已移除模块。
  • `requirements[].id` 唯一。
  • `dataPath` 能从 `dataModel.value` 解析。
  • action requirement 必须包含合法 `onClick`。

模型输出后

  • 只包含一个 `genui` 代码块。
  • 不包含 `cardspec` 代码块。
  • genui 恰好 3 行 JSONL。
  • `updateDataModel.value` 等于 `TaskSpec.dataModel.value`。
  • root 尺寸为 140x140 或 300x140。
