TaskSpec Protocol · taskspec/v1

TaskSpec 是大模型交给小模型的轻量任务契约

它不描述具体布局，不预写组件树，只把用户需求中与 Form 协议有关的内容项、数据能力、事件能力、CardSpec 和 DSL 硬约束整理清楚。小模型拿到它之后，最终只生成 genui DSL。

轻量只写约束和契约，不写半成品 DSL。
可校验schema 约束结构，脚本检查引用一致性。
职责分明大模型生成 TaskSpec，小模型只生成 DSL。
CardSpec 前置CardSpec 属于 TaskSpec，不由小模型输出。
Boundary

协议边界

TaskSpec 的价值在于把“大模型理解”收敛成“小模型可以稳定执行”的输入。它应该足够明确，但不能把布局设计空间全部写死。

TaskSpec 应该包含

卡片场景、尺寸、必须表达的内容项、DataModel 初始值、动态数据能力、点击事件能力、素材清单、CardSpec、DSL 输出硬约束，以及可选的校验记录。

TaskSpec 不应该包含

具体布局树、组件层级、根 shell、区域划分、宽度预算、视觉排版细节、完整 genui JSONL，或任何要求小模型照抄的半成品 DSL。

Top Level

顶层字段与是否必填

下面字段来自当前 `taskspec.schema.json`。顶层禁止额外字段，除 `capabilityGap` 与 `validation` 外，其余字段都是必填。

字段 是否必须 说明 示例
schema必须TaskSpec 协议版本，固定为 `taskspec/v1`。"taskspec/v1"
rulesVersion必须Form DSL 规则集版本，固定为 `harmony-form-rules/v1`。"harmony-form-rules/v1"
userQuery必须原始用户需求，保留语义来源，便于追踪。"显示深圳温度并给我爸打电话"
task必须给小模型的任务说明，必须约束只输出 genui。"直接输出 genui 代码块..."
card必须卡片场景、尺寸、内容需求和可选设计约束。{"scenario":"device","size":"2x4"}
dataModel必须小模型第 3 行 updateDataModel.value 必须原样使用的数据。{"value":{"device":{...}}}
cardSpec必须大模型已经确定的端侧 CardSpec，小模型不得生成或改写。{"suggestSize":"2x2"}
dataCapabilities必须动态数据能力清单；静态卡也要给空数组。[]
eventBindings必须可点击动作清单；没有动作时给空数组。[{"eventRef":"call_dad",...}]
assets必须允许使用的素材清单；没有素材时给空数组。[]
rules必须本次 DSL 生成必须遵守的硬约束。{"dsl":["只输出 genui..."]}
capabilityGap可选能力不足或无法映射时的说明。"未找到日程查询能力"
validation可选生成 TaskSpec 时已检查的项目记录。{"level":"strict","checked":[...]}
Modules

具体模块说明

每个模块都说明它解决什么问题、是否必须、内部字段怎么用，以及一段来自项目样例的具体写法。

MODULE 01

版本与任务

`schema`、`rulesVersion`、`userQuery`、`task`

必须 这组字段定义协议版本、规则版本、原始输入和小模型任务边界。`task` 要明确小模型只输出一个 genui 代码块，不输出解释、标题、路径、总结或 cardspec。

示例 
{
  "schema": "taskspec/v1",
  "rulesVersion": "harmony-form-rules/v1",
  "userQuery": "给我做个好看的耳机桌面卡片...",
  "task": "根据本 TaskSpec 生成一个 genui 代码块（A2UI JSONL，每行一个 JSON object，共 3 行）。直接输出 genui 代码块，不要输出解释、标题、路径、总结或 cardspec 代码块。"
}
MODULE 02

card

卡片意图，不是布局方案

必须 `card.scenario` 表达场景，`card.size` 只决定 root 目标尺寸，`card.requirements` 是必须被表达的内容项。`constraints` 可选，用于补充风格、完整显示、优先级等自然语言约束。

scenario用于告诉小模型这张卡的主要意图，影响信息优先级、视觉语气和交互密度。
size可选 `2x2` 或 `2x4`，分别对应 160x160 与 320x160。
requirements.type用于告诉小模型每个内容项在卡片里的语义角色，影响字号、位置、组件和点击处理。

scenario 选项说明

status
状态展示卡，突出当前状态或实时结果，例如天气、健康、设备在线状态。
reminder
提醒/待办卡，突出时间、截止点、下一步动作，例如日程、服药、缴费提醒。
action
快捷操作卡，核心价值是点击入口，例如拨号、打开应用、执行一个服务动作。
device
设备信息卡，突出设备名称、指标、连接状态和快捷入口，例如耳机电量、家电状态。
summary
摘要概览卡，展示多项信息的汇总，例如今日概览、消费摘要、运动摘要。

requirements.type 选项说明

identity
身份/对象名，例如城市、联系人、设备名，通常作为标题或识别信息。
primary
主信息或主答案，例如当前温度、余额、最重要的状态，通常最醒目。
metric
数值指标，例如电量、步数、百分比，可用于文本或进度表达。
status
状态文本，例如感冒指数、在线/离线、风险等级。
context
辅助上下文，例如天气状况、更新时间、副标题，不应抢主信息层级。
media
图片或图标类内容，通常需要配合 `assetRef` 或静态素材。
action
可点击动作入口，必须通过 `eventRef` 关联 `eventBindings`。
style
视觉风格要求，例如磨砂玻璃、高级、温暖，用于约束视觉表达，不对应数据绑定。
示例 
{
  "scenario": "device",
  "size": "2x4",
  "requirements": [
    { "id": "device_name", "type": "identity", "label": "Free Clip 2", "dataPath": "/device/name", "required": true },
    { "id": "left_battery", "type": "metric", "label": "左耳电量", "dataPath": "/device/leftBatteryText", "required": true },
    { "id": "daily_30", "type": "action", "label": "每日30首", "eventRef": "open_daily_30", "required": true },
    { "id": "frosted_style", "type": "style", "label": "磨砂玻璃质感", "note": "半透明层次、柔和边框、克制色彩。" }
  ],
  "constraints": ["整体简洁高级，有磨砂玻璃质感。"]
}
MODULE 03

dataModel

小模型必须原样写入的初始数据

必须 `dataModel.value` 是小模型生成第三行 `updateDataModel.value` 时必须原样使用的对象。静态数据可以直接放在这里；动态数据可以放加载态默认值，并由 `cardSpec.dataBindings` 写回。

示例 
{
  "value": {
    "device": {
      "name": "Free Clip 2",
      "leftBatteryText": "左耳 47%",
      "rightBatteryText": "右耳 95%",
      "leftBatteryPercent": 47,
      "rightBatteryPercent": 95
    }
  }
}
MODULE 04

cardSpec

大模型确定的端侧契约

必须 `cardSpec.suggestSize` 必须等于 `card.size`。静态卡通常只有 `suggestSize`；动态卡需要 `dataBindings`，并与 `dataCapabilities` 对齐。小模型最终输出不包含 CardSpec。

动态天气卡示例 
{
  "suggestSize": "2x2",
  "dataBindings": [
    {
      "capabilityId": "ViewWeather",
      "arguments": {
        "districtName": "深圳",
        "prefectureName": "深圳",
        "forecastDays": 1
      },
      "writeResultTo": "/data/weather"
    }
  ]
}
MODULE 05

dataCapabilities

动态数据能力与可绑定路径

必须 这是数组字段。动态卡列出能力、参数、写入位置和会被卡片使用的输出路径；静态卡也必须写成空数组 `[]`。

示例 
[
  {
    "capabilityId": "ViewWeather",
    "arguments": { "districtName": "深圳", "prefectureName": "深圳", "forecastDays": 1 },
    "writeResultTo": "/data/weather",
    "usedOutputPaths": [
      { "field": "temperatureText", "path": "/data/weather/current/temperatureText", "desc": "当前温度文本。" },
      { "field": "coldLevel", "path": "/data/weather/current/coldLevel", "desc": "感冒指数。" }
    ]
  }
]
MODULE 06

eventBindings

点击事件能力

必须 这是数组字段。每个 `eventRef` 必须能被 `card.requirements[].eventRef` 引用。小模型只允许使用这里声明的事件，不应发明新动作。

示例 
[
  {
    "eventRef": "call_dad",
    "on": "给爸打电话入口",
    "onClick": [
      {
        "call": "clickToCallPhone",
        "args": { "phoneNumber": "15012345678" }
      }
    ]
  }
]
MODULE 07

assets

素材白名单

必须 这是数组字段。没有素材时写 `[]`；有素材时需要声明 `src` 和 `use`，可选 `assetRef`、`bindTo`、`static`。小模型只能使用这里声明的素材。

示例 
[
  {
    "assetRef": "headphone_bg",
    "src": "assets/headphone-bg.png",
    "use": "background texture",
    "static": true
  }
]
MODULE 08

rules.dsl

本次 DSL 硬约束

必须 `rules.dsl` 只放硬规则，不放具体布局方案。通用规则由转换脚本放进 `system` prompt，TaskSpec 里保留本次必须强化的约束。

推荐最小规则集 
[
  "只输出一个 genui 代码块，不输出 cardspec 或解释文字。",
  "genui 恰好 3 行 JSONL，顺序为 createSurface、updateComponents、updateDataModel。",
  "updateDataModel.path 必须是 /，value 必须等于 TaskSpec.dataModel.value。",
  "root 尺寸按 card.size：2x2=160x160，2x4=320x160。",
  "onClick 只使用 TaskSpec.eventBindings 中声明的事件。",
  "绑定使用 {\"path\":\"/...\"} 或 formatString，不使用表达式。"
]
MODULE 09

validation / capabilityGap

可选的生成记录和能力缺口

可选 `validation` 记录大模型生成 TaskSpec 时已检查的项目；`capabilityGap` 用于说明当前能力无法完整满足用户 query 的地方。它们不替代脚本校验。

示例 
{
  "validation": {
    "level": "strict",
    "checked": [
      "card.size equals cardSpec.suggestSize",
      "small model only outputs genui"
    ]
  },
  "capabilityGap": "未找到可用的数据能力时，在这里说明缺口。"
}
Validation

校验要点

TaskSpec 有两段校验：发送给小模型前校验 TaskSpec，本地拿到模型输出后校验 DSL。校验脚本是协议稳定性的护栏。

发送给小模型前

  • JSON 结构符合 `taskspec.schema.json`。
  • `card.size` 等于 `cardSpec.suggestSize`。
  • `requirements[].id` 唯一。
  • `dataPath`、`eventRef`、`assetRef` 引用可追踪。
  • 动态卡 `cardSpec.dataBindings[]` 与 `dataCapabilities[]` 对齐。

模型输出后

  • 只包含一个 `genui` 代码块。
  • 不包含 `cardspec` 代码块。
  • genui 恰好 3 行 JSONL。
  • `updateDataModel.value` 等于 `TaskSpec.dataModel.value`。
  • root 尺寸与 `TaskSpec.card.size` 一致。
