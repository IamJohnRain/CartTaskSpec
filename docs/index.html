⚡ 大模型 + 小模型 协作生成协议

把卡片生成拆成两层：
理解力交给大模型，结构化输出交给小模型

大模型产出一个轻量的 TaskSpec，只携带卡片目标、数据/事件能力与 DSL 硬约束；小模型只依据它把卡片「画」出来。布局不再写死在协议里，CardSpec 由大模型直接交付端侧。

协议 taskspec/v1
规则集 harmony-form-rules/v1
输出 genui JSONL × 3 行
CardSpec 大模型前置确定
设计思想

轻量契约，而不是半成品 DSL

TaskSpec 描述「要显示什么、要调用什么、必须遵守什么」，不描述「怎么排」。布局、组件嵌套、视觉表达都交回小模型实现。

🎯

目标驱动

TaskSpec 只声明卡片场景、尺寸、内容项与约束。小模型拿到的是「需求」，不是「施工图」，留出真正的设计空间。

🧩

职责收窄

大模型做理解和取舍（场景、能力、CardSpec），小模型做落地（组件树、样式、视觉）。两层单向收窄，边界清晰。

📐

可校验

结构形状用 JSON Schema，引用一致性、项目约束、模型输出各有独立校验脚本，任何一环出错都能拦截。

职责边界

🟢 大模型 — 理解与决策
  • 场景识别、尺寸选择、能力边界判断
  • 语义内容项 card.requirements
  • DataModel 形状与初始值
  • CardSpec（静态/动态 dataBindings）
  • 事件能力 eventBindings 预填 onClick
  • DSL 硬约束 rules.dsl
🟣 小模型 — 布局与实现
  • 组件嵌套结构、id 命名
  • 样式、颜色、字号、间距
  • 视觉层次与拥挤行宽度预算
  • 落成合法 DSL JSONL（恰好 3 行）
  • 把 eventBindings 的 onClick 挂到组件
  • 不得生成或改写 cardSpec

项目结构

      
每个文件各司其职

      
协议权威在 TaskSpec.md 与 taskspec.schema.json；skill 目录只读，禁止修改。

    

    
# CartTaskSpec/
├── README.md                      项目说明
├── TaskSpec.md                    TaskSpec 协议规范（项目权威）
├── taskspec.schema.json           JSON Schema (Draft 2020-12)
├── taskspec_to_chat_completions.py TaskSpec → 请求体
├── validate_taskspec.py           结构 + 引用一致性校验
├── validate_generated_card.py     小模型 genui 输出校验
├── validate_project_constraints.py.agents/skills 只读检查
├── examples/
│   ├── parent-care.taskspec.json      动态天气 + 拨号
│   └── freeclip2-earbuds.taskspec.json静态设备 + 音乐入口
├── references/
│   ├── chat-completions-api.md
│   └── test_api.sh
└── .agents/skills/harmony-card-generation/  外部只读 skill（禁止修改）

  






  

    

      
常用命令

      
一条龙跑通

    

    
# 1. 校验 TaskSpec 结构与引用一致性
python validate_taskspec.py examples

# 2. 确认 skill 只读约束未被破坏
python validate_project_constraints.py

# 3. 生成请求体并调用本地小模型接口
python taskspec_to_chat_completions.py examples\parent-care.taskspec.json `
  -o request.json --invoke --response-output response.json

# 4. 校验模型生成的 genui 并提取 DSL
python validate_generated_card.py `
  --response response.json `
  --spec examples\parent-care.taskspec.json `
  --out-dir generated --name parent-care
