taskspec/v1 · harmony-form-rules/v1

把 Form 协议约束抽取出来，让小模型更会画卡片

CartTaskSpec 不是把理解力简单交给大模型，而是让大模型从用户 query 中抽取与 Form 协议相关的约束、能力和交付契约；小模型在清晰边界内完成真正有价值的 DSL 设计与生成。

查看作业流 TaskSpec 协议详解 GitHub 仓库
Large Model

抽取约束，而不是写死布局

识别场景、尺寸、数据能力、事件能力、CardSpec 和 DSL 硬规则。

Small Model

在约束内完成高质量实现

完成组件组织、视觉层次、排版、绑定和最终 3 行 genui JSONL。

Final Output

只交付 genui DSL

CardSpec 已在 TaskSpec 中确定，小模型最终输出只有 DSL，不再生成或组合 cardspec。

Design Philosophy

协议设计思想

TaskSpec 的核心不是替小模型完成布局，而是把 Form 卡片生成中必须遵守的协议规则、数据契约和事件边界整理成一个短小、可校验的输入。

1

从 query 抽取 Form 约束

大模型的价值在于把自然语言需求变成结构化约束：显示字段、动态能力、点击能力、CardSpec、禁止项和输出格式。

2

保留小模型的设计空间

TaskSpec 不携带布局树、区域预算或组件嵌套。小模型负责把需求转成可渲染、可读、可交互的 DSL。

3

用校验兜住边界

小模型可以发挥布局和视觉能力，但必须通过 JSONL、组件、绑定、事件、DataModel 和尺寸校验。

大模型负责抽取什么？

不是产出完整卡片，而是把与协议有关的决策抽出来。

  • 内容约束：哪些信息必须出现、哪些字段要完整显示。
  • 能力约束：data capability、event capability、参数和写入路径。
  • 交付约束：cardSpec、rules.dsl、输出禁止项。

小模型的核心价值是什么？

小模型不是剩下组装，而是在明确约束内完成卡片设计落地。

  • 布局判断：根据 2x2/2x4 空间组织信息层级。
  • 组件实现：选择 Row/Column/Stack/Text/Button 等并生成扁平组件数组。
  • 视觉表达：处理留白、字号、颜色、层次、点击区域和拥挤文本。
  • 协议落地：输出严格 3 行 JSONL，并保持 DataModel 和事件绑定一致。
Workflow

三个中间模块：从用户 Query 到 DSL

流程只突出三个真正处理信息的模块：大模型 Agent、转换脚本、小模型 API。用户 Query、TaskSpec（含 CardSpec）、API request body 和 DSL 都是这些模块之间流动的输入输出；最终输出只有小模型生成的 DSL。

MODULE01

大模型 Agent

输入

用户 Query，以及 Form 协议 / skill 参考规则。协议结构以 taskspec.schema.json 为准。

输出 + 校验

TaskSpec JSON，内含 `card.requirements`、`dataModel`、`eventBindings`、`rules.dsl` 和 `cardSpec`；随后执行 schema 与协议一致性校验。

展开输入样例：用户 Query 
给我做个好看的耳机桌面卡片，显示 Free Clip 2 和左右耳机电量（47%、95%），下面放每日30首和心动歌单两个快捷入口，简洁高级一点，有磨砂玻璃那种感觉。
展开输出样例：TaskSpec（含 CardSpec） 

              

              

                展开校验环节：schema + 协议一致性
                
python validate_taskspec.py examples\freeclip2-earbuds.taskspec.json

校验重点：
- JSON 结构符合 taskspec.schema.json
- card.size 与 cardSpec.suggestSize 一致
- dataPath / eventRef / dataBindings 引用可追踪
- 小模型任务被约束为只输出 genui DSL

              

            

          


          

            
MODULE02

            

              
转换脚本

              

                
输入
TaskSpec JSON 文件，即上一步大模型 Agent 的输出。

                
输出
OpenAI 兼容 API request body，包含 `system` prompt 和 `user` TaskSpec。

              

              

                展开输入样例：TaskSpec 文件
                
examples\freeclip2-earbuds.taskspec.json

              

              

                展开输出样例：API request body
                
python taskspec_to_chat_completions.py examples\freeclip2-earbuds.taskspec.json -o request.json

{
  "model": "glm-5.2",
  "messages": [
    { "role": "system", "content": "你是 HarmonyOS A2UI Form DSL 生成器..." },
    { "role": "user", "content": "根据下面的 TaskSpec JSON 生成响应..." }
  ]
}

              

            

          


          

            
MODULE03

            

              
小模型 API

              

                
输入
API request body。`system` 说明 DSL 规则，`user` 提供完整 TaskSpec。

                
输出
DSL：一个 `genui` 代码块，恰好 3 行 JSONL。最终输出只有 DSL，不包含 CardSpec，也不做 DSL + CardSpec 组合产物。

              

              

                展开输入样例：请求模型
                
python taskspec_to_chat_completions.py examples\freeclip2-earbuds.taskspec.json \
  -o request.json \
  --invoke \
  --response-output response.json

              

              

                展开输出样例：DSL
                
```genui
{"version":"v0.9","createSurface":{"surfaceId":"card","catalogId":"ohos.a2ui.extended.catalog"}}
{"version":"v0.9","updateComponents":{"surfaceId":"card","components":[...]}}
{"version":"v0.9","updateDataModel":{"surfaceId":"card","path":"/","value":{...}}}
```
